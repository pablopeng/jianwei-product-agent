# 商品档案确认与卖点优先级

优先级目前是模型的编辑排序，1最高，不是固定权重的分数，也不是转化预测。先排除缺证与冲突声称，再综合购买决策价值、商品具体差异、用户关注点、证据充分性。核心体验或关键差异通常靠前，便利、规格、服务随后；用户明确要求便携或送礼时可以调整。前端结果区提供排序说明。

新交互：用户给出资料并要求卖点 → Agent整理五块商品档案 → 展示、等待用户检查 → 直接编辑或自然语言修改 → 确认当前版本 → 生成卖点。普通咨询、核查和局部改写仍按用户意图处理。

档案直接显示商品信息、规格配料、原有卖点、买家反馈、待确认项，可在对话页面用表单修改、增删条目和规格。自然语言修改通过专门工具处理，保留未要求修改的内容。商家新增内容记录为商家补充，不等于取得第三方认证；后续生成仍受原有证据和声称边界约束。

首次整理后，生成工具不能越过确认。按钮确认绑定当前档案版本；自然语言确认只能针对本轮开始前已展示、且本轮未修改的档案。已确认且未变化的档案可继续生成或改写，无需反复确认。

每次档案变更保留完整版本与确认时间。修改会取消旧确认并清空旧卖点；新增原始资料会使当前档案过期，需重新整理确认。保存使用版本校验，过时编辑不能覆盖新版本。原始资料、用户更正和历史档案均保留，当前档案与版本可导出JSON，方便评测。第一阶段即使尚未生成卖点，也可以独立运行事实AI核查。

确认表示商家确认使用当前档案，不表示系统已经证明其中每项事实正确。待确认项可保留并在生成时避开，不要求先补齐所有材料。
