# 从商家案例到卖点评测：首版设计

本轮目标是让卖点既完整、有购买价值，也有可读的表达层次。不能用吸睛分掩盖事实错误，不能将机评通过等同于真实转化提升。

## 2. 案例带来的写作洞察

| 洞察 | 可复查的图片案例 | 对生成策略的影响 |
|---|---|---|
| 短标题抓一个点，细节解释为什么 | 行152 H“创新密封盖”，配“随用随盖”；主图另有“用量可控” | 不只报包装属性，展开实际取用动作；不要推导永久保鲜 |
| 工艺、原料、体验分开讲，组起来才完整 | 行27 I“三重发酵”、J分别展示花生/蜂蜜/芝麻、K独立包装 | 建立候选价值清单，再合并同义点；不能只生成三句“好吃” |
| 场景能把抽象价值落地 | 行10 H“早餐灵魂”配吐司，J“只有黑芝麻，纯粹如初”配菜；行23 H“大餐后来一条” | 用真实产品特征连接具体使用时刻；场景不是功效证明 |
| 感官应具体、有层次 | 行135 J“软糯黏稠，滑溜米油”；行190 G/H/I分别呈现干茶、茶汤、叶底 | 写质地、动作、香气等已知体验；无依据不能造爆浆、拉丝、脆响 |

| 同商品不同SKU需保留差异 | 行18 H/I/J分别列三种烤鱼调料的标签与口味 | 不把一种口味原料搬到其他口味；必要限定写进标题或正文 |

| 丰富并不等于所有内容都要重写 | 行55大部分为相近食物展示，文字信息重复 | 一张图不必对应一条新卖点；评价/物流/回购也不自动成为核心理由 |

反面样例也很重要：行63 J出现“不用挨饿”，行28 I用其他食品图示进行营养类比，行2候选文字把“不添加白砂糖”缩成“0糖”。这些只能作为风险案例，不能照学；这里没有对商家作法律合规结论。

**推荐表达单元**：`短标题｜1—3句展开`，存在同一个text中；可以按用户要求只写标题、短句或较长展开。4—12字只是标题参考，不硬限。比喻是可选手法，不是单独加分项；具体直接的句子同样能拿高分。

## 3. 第一层：准确性机评

“对就是对”仍需要可执行定义。检查对象包括原始资料→第一阶段摘要、第一阶段→第二阶段文案，并让卖点回到原始资料复核，防止第一阶段错了、第二阶段照抄却被判正确。

检查单元为档案条目和每条卖点；卖点内部的事实拆开核对。数值、单位、符号、配料、SKU范围、套装、加工/食用条件、归因、功效和认证都在范围内。每项输出：判断、简短原因、来源ID与原文；图片需要实际送入模型，不能只传图片文件名。

| 判断 | 定义 | 处理 |
|---|---|---|
| supported / 有据 | 整条事实均有证据，范围正确，修辞未增加承诺 | 保留，仍人工抽检 |
| contradicted / 冲突 | 有明确相反原文，或把某款参数扩到其他款 | 隔离、回查并修复 |
| insufficient / 待核 | 缺证、有歧义、只支持部分断言，或来源互相矛盾 | 不做确定性承诺，交人工确认 |

不能把“未提及”判成“明确反证”。规则校验只证明引用存在/结构有效；语义机评也会漏判。引用的文本原文需要程序核对，错误引用不能判通过。对缺证卖点可以删改，不能因为一个缺口阻止其他有据卖点。

## 4. 第二层：跨行业底线与质量Rubric

底线四项：**事实有据、范围与归因、承诺不过度、比较有据且不贬损**。每项0分=明确错误，1分=缺证/争议待复核，2分=核对后未发现该类问题。任何0分则不通过，有1分则待复核，全部2分才底线通过；未评不能默认为通过。它们不参与质量加权。

质量以整组卖点评分，每项0/1/2。评审仍要指出具体条目、漏点或重复点，而不是只给平均分。

| 维度/权重 | 定义 | 0分 | 1分 | 2分 |
|---|---|---|---|---|
|有效卖点覆盖 / 20%|整组文案是否覆盖档案中重要、可用且独立的购买理由；不奖励条数。|遗漏核心可用理由，或主要篇幅被重复卖点占用。|核心理由基本覆盖，但仍遗漏一个重要角度或存在可合并重复。|重要且可用的原料/功能、体验、使用和规格等理由覆盖充分，互不重复；资料没有的维度不强求。|
|购买价值展开 / 20%|是否把商品特征转成清楚、具体的选择理由，避免只有参数或空泛赞美。|只有参数罗列或品质好等套话，看不出为何要选。|部分特征解释了用途或价值，但仍有空泛、跳步或不必要的铺陈。|关键特征均有恰当的体验或使用价值解释，消费者知道它解决什么需要；不要求为每个参数硬造利益。|
|商品辨识与排序 / 15%|是否抓住当前商品可证实的具体特点，并优先展示最重要的理由。|换个商品名仍基本通用，或前几条全是物流、泛好评等次要内容。|有具体特点，但核心理由被埋后，或若干条仍像通用模板。|前几条体现该商品最有价值的具体特点，次要理由随后展开，不虚构独家或领先。|
|标题吸引力 / 15%|短标题或开头能否在快速浏览中传达具体卖点并留下记忆点；不是标题党。|标题空洞、难懂、重复或仅喊促销口号。|意思清楚且有产品信息，但平淡、冗长或相互雷同。|开头简洁有力，突出具体好处/细节/体验，有节奏或记忆点；不靠夸大吸睛。|
|展开的具体与鲜活 / 20%|正文是否在标题之外增加有效细节，帮助想象体验或使用；修辞是可选手段。|正文只复述标题，或堆华丽形容词、无意义比喻。|有有效细节或场景，但部分展开仍薄弱、生硬或同质化。|用适量动作、感官、使用细节或恰当类比让价值可感知，正文增加信息；资料简少时直接具体的短句也可得高分。|
|易读与适配 / 10%|每条是否聚焦、自然、容易扫描，长度与信息量、用户要求匹配。|长句堆砌、多主题混杂或内部分析话术，难以直接使用。|基本顺畅，但部分条目过密、割裂、格式或语气不一致。|一条一个重点，长短有层次，限定贴近相关承诺，符合用户语气及输出形式要求。|

质量分 = Σ(维度得分×权重) / Σ权重，范围0—2。它是编辑评审量表，不是转化率预测；吸引力和鲜活度允许审美差异。底线未通过时仍可记录质量分用于诊断，但不能标记整体通过。

覆盖度以“重要且可用的候选购买理由”为分母，不以原始资料条数、固定类目模板或卖点数量为分母。准确但重要性低的保质期不一定排第一。区分“价值展开”（为什么值得选）与“鲜活展开”（如何具体可感知），避免同一个优点重复给分。

## 5. 评测集与迭代闭环

当前14个商品适合做小样本迭代，不足以证明跨行业泛化。先按PID和原图来源分组，重复行、相同SKU图、同商品改标题不可跨训练/开发/留出集合。Sheet1发现的PID冲突先人工处置。按饮料/零食/调料/速食/生鲜等分层，建议现有14条分为开发10条、冻结留出4条，实际分配在补充独立人工审核后冻结；本轮尚未完成这14条的盲评。

另外建设错误挑战集：SKU配料误用、净重/套装混淆、>与≥、无添加糖与无糖、评价变保证、缺证认证、加工条件错误、旧AI注入、冲突参数、比喻暗示新性能，以及跨行业的尺寸、材质、性能测试范围。挑战样例用于检验规则，不混算为真实商品效果。

短期每轮固定输入档案、模型、生成要求，随机打乱改前改后版本，人工先核底线再给六项分；至少两人独立评一部分，讨论0与2的分歧并改锚点。机评缺证与争议保留原文，不以多数投票消除事实冲突。分别记录底线通过率、事实错误/缺证分布、重要卖点漏点、分项质量分、人工两两偏好和耗时；不把字数、条数增长当进步。

用错误定位修改点：原文理解错→输入解析/第一阶段；范围或来源丢失→档案与归因；档案正确但生成夸大→第二阶段；事实准确却薄→候选价值/表达策略；评审分歧大→Rubric锚点。每次只改能解释问题的部分，冻结留出集不参与提示词修改；版本变化保留输入、输出、Prompt、模型、Rubric和判断证据。

## 6. Auto Rubrics与SFT的长期路径

保留通用底线和质量骨架，行业Rubric只补充关键决策维度与正反例。Auto Rubrics先从优质/差质案例及人工改写中提出候选标准，附来源、反例、适用条件和可观察锚点；再去重、查冲突、人工确认，并在未参与提炼的新案例上检验一致性。不能让模型自己写标准、自己打高分就自动认定有效，也不能把商家夸张话术学成奖励。

未来SFT保留第一阶段规范档案作为稳定输入，目标仍可为text+priority，包含短标题与展开。只使用通过事实核查和人工质量审阅的目标；保留被拒候选、错误标签与人工修订，便于后续偏好训练。按商品/原图划分训练与验证，避免同款泄漏。保存行业、证据边界、用户形式要求和Rubric版本。是否需要SFT，应由跨案例的稳定瓶颈和基线对照决定；本轮未进行训练或Auto Rubrics自动上线。

## 7. 本轮落地

已更新主Agent、第一阶段摘要提示词、食品饮料Skill；第二阶段仍只有文案和优先级，支持标题与展开。评测工作台已配置四项底线、六项质量、三档定义、独立底线状态，并接入逐条事实AI核查与可导出报告。生成和核查相互独立，核查结果不会自动当成新商品事实，也不会自动改写或删除用户资料。

生成工具另有终稿编辑复核，用于删改无依据的展开和重复卖点；可在提示词页修改“第二阶段 · 终稿复核”。实际对照与未解决项见《本轮质量迭代验证》，不能把机评缺证项或失败尝试当作通过。主Agent依旧按用户意图选择工具。
